> 对应设计：
> `docs/superpowers/specs/2026-07-24-README-双语视觉重构设计.md`

## 实施原则

- 本次只修改文档、文档视觉资产、文档契约测试和 `.gitignore`。
- 不修改 CLI 行为、包依赖、发布工作流或 npm tarball 文件范围。
- 所有命令描述以 `src/cli.ts`、`src/commands/` 和现有测试为准。
- 所有录制和渲染使用隔离的临时主目录，绝不读取真实用户配置。
- 英文与中文 README 作为同一个功能交付，不允许只完成其中一份。
- 仓库目前只有 Release 触发的 npm 发布工作流，没有常规 PR/main CI；首屏不放
  误导性的 “CI passing” 徽章，也不在本任务中扩展 CI 范围。

## 任务 3：制作 Midnight Sync Banner

**文件**

- 新增：`docs/assets/readme/codexkeep-banner.svg`

**步骤**

1. 创建无脚本、无外部字体、无外链图片的自包含 SVG。
2. 使用 1600×480 画布和深色紫蓝径向渐变。
3. 左侧放置：
   - `PORTABLE CODEX CONFIG`；
   - `CodexKeep`；
   - 一句短定位；
   - `portable config`、`private by default`、`recoverable writes` 三枚轻量
     标签。
4. 右侧使用规则网格绘制：

   ```text
   This Mac → Private Git → New Mac
   ```

   拓扑只表达产品概念，不伪装成精确同步算法。
5. SVG 内提供 `<title>` 和 `<desc>`，保证独立查看时有可访问描述。
6. 使用本地浏览器分别按宽屏和窄屏宽度打开 SVG，并生成临时截图检查：
   - 不重叠；
   - 最小文字仍可读；
   - 渐变与连线对比度足够；
   - 没有依赖当前机器字体或绝对路径。
7. 检查体积：

   ```bash
   wc -c docs/assets/readme/codexkeep-banner.svg
   ```

## 任务 4：录制真实终端演示

**文件**

- 新增：`docs/assets/readme/codexkeep-demo.gif`
- 临时但不提交：隔离主目录、本地 bare Git 仓库、VHS tape 和录制中间文件

**步骤**

1. 先运行 `pnpm build`，确保录制的是当前 CLI。
2. 使用 `mktemp -d` 创建隔离目录，并在退出时清理。
3. 在隔离目录内：
   - 设置专用 `HOME`、Git 作者信息和 Codex 路径；
   - 创建本地 bare Git 远端；
   - 使用构建产物运行 `codexkeep init <local-remote> --yes`；
   - 添加一项无敏感数据的演示 skill，使随后同步有真实变更；
   - 创建只存在于临时 `PATH` 的 `codexkeep` 包装入口，显示给观众的命令仍是
     `codexkeep sync --yes`。
4. 使用一次性终端录制工具生成约 10–15 秒 GIF。录制工具只安装在用户批准的
   本地工具环境，不加入 `package.json` 或锁文件。
5. GIF 只展示真实输出：

   ```text
   codexkeep sync --yes
   → 完整预检
   → 同步计划
   → 保存并上传
   → 同步完成
   ```

6. 逐帧检查并确认画面不包含：
   - 真实用户名或仓库；
   - token、credential、session；
   - 用户主目录绝对路径；
   - 真实 Codex 配置。
7. 将分辨率控制在 README 可读范围，体积控制在 3 MB 内。
8. 如果录制工具无法安全安装、GIF 超过体积限制或文字压缩后不可读，则按设计
   规格降级为同风格静态终端 SVG，并同步调整文档契约测试和 README 引用；
   不提交巨大或伪造的动画。

## 任务 5：重写英文 README

**文件**

- 修改：`README.md`

**步骤**

1. 添加顶部语言切换：

   ```text
   English | 简体中文
   ```

   两个入口都使用 `github.com/HenryOoO/codexkeep/blob/main/` 下的绝对 URL，
   保证未包含中文文件的 npm tarball 页面也能正确跳转。
2. 使用绝对 HTTPS 地址嵌入 Banner 和终端演示：

   ```text
   https://raw.githubusercontent.com/HenryOoO/codexkeep/main/docs/assets/readme/...
   ```

3. 添加真实状态徽章：
   - npm 当前版本；
   - Node.js 22+；
   - MIT License。

   不把只在 GitHub Release 时运行的 `publish.yml` 标注为常规 CI。
4. 按设计规格重组章节：
   - 30-second start；
   - terminal demo；
   - how it works；
   - first device / another device / daily sync；
   - command reference；
   - synchronized / never synchronized；
   - data model and links；
   - troubleshooting；
   - development and release。
5. 在工作原理章节加入英文 Mermaid 图，分别表示可移植配置主流程和始终留在
   本机的排除项。
6. 为 `codexkeep`、`init`、`sync`、`update`、`check`、`remote` 和 `link`
   编写统一格式的说明：
   - when to use；
   - invocation；
   - network；
   - changes；
   - confirmation；
   - conflicts；
   - recovery。
7. 准确记录已确认的行为：
   - 新设备通过 `init <git-url>` 加入已有仓库；
   - `link` 只恢复本地官方路径符号链接，不联网；
   - `check` 是只读本机诊断，不访问 Git 远端；
   - `update` 先升级有来源记录的 skills 和 marketplaces，再运行同步；
   - `remote` 无参数时只读查看，有 URL 时只连接空远端并进入同步；
   - `--yes` 接受常规确认，但不替用户选择内容冲突的一方。
8. 保留非官方项目声明、Node/Git/macOS 要求、数据模型和发布说明。
