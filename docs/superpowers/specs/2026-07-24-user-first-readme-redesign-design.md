# CodexKeep 用户优先 README 重构设计

## 背景

当前英文 `README.md` 约 400 行，中文 `README.zh-CN.md` 约 370 行。两份文档
同时承担产品首页、快速上手、完整命令手册、数据模型、故障恢复和维护者说明，
虽然信息准确且完整，但新用户进入命令参考后很难继续形成清晰的产品认知。

现有终端 GIF 也不适合作为产品演示。它使用一次性 VHS 录制流程生成，最终文件
为 1120×620、约 13 秒，但生成所需的 tape、字体和终端布局参数没有提交。
画面存在中英文异常字距、内容集中在左上角、有效信息密度低等问题。现有测试只
检查文件存在、大小和引用地址，没有验证最终可读性。

本设计将 README 从“完整说明书”重构为“产品介绍与用户入口”，让读者先理解
价值、建立信任并完成首次使用，再按需进入详细文档。

本设计是当前 README 重构的唯一设计依据。CLI 行为和安全边界仍以当前实现与
测试为准。

## 目标

- 默认 README 使用简体中文，并提供完整英文版本。
- 用一句明确承诺说明核心价值：通过用户掌控的私有 Git 仓库，用一条命令在
  多台 Mac 间同步个人 Codex 配置。
- 让新用户能在短时间内完成安装和第一台设备初始化。
- 在不过度展开实现细节的前提下，说明同步范围、隐私边界和失败保护。
- 将完整命令行为、数据模型和恢复指南迁入结构清楚的双语用户文档。
- 删除不可读且不可复现的终端 GIF，使用可读、可搜索的终端文本示例。
- 将现有 Midnight Sync 视觉收敛为一张经过实际尺寸验收的产品横幅，不再用
  通用徽章或默认流程图堆叠视觉元素。

## 非目标

- 不修改 CLI 命令、输出、同步算法、数据格式或安全策略。
- 不新增运行时或文档构建依赖。
- 不建设独立官网或文档站点。
- 不为 README 增加更多装饰性图片、营销卡片或复杂 HTML 布局。
- 不把完整实现文档复制到用户指南。
- 不在本次改动中重新录制终端 GIF。

## 已考虑的方向

### 采用：产品型 README 与双语文档中心

README 控制在约 150 至 200 行，承担产品定位、快速上手、核心流程、安全摘要、
命令速查和详细文档导航。完整行为说明放入双语 `docs/` 文件。

这个方向在试用转化与安全可信度之间最平衡。代价是查询细节时需要跳转，但清晰
导航可以降低这一成本。

### 不采用：单 README 渐进展开

把完整说明继续保留在 `<details>` 中可以减少表面长度，但没有解决内容职责
混杂的问题，页面源文件和搜索结果仍然沉重。

### 不采用：极简产品页

只保留定位、安装和文档链接会有更强的宣传效果，但 CodexKeep 会管理个人配置，
如果缺少具体安全边界，用户难以在运行前建立足够信任。

## 产品定位与首屏

主要读者是希望在多台 Mac 间保持个人 Codex 工作环境一致的 Codex 用户。
README 的首要目标是促使读者安装和初始化，次要目标是在运行前用具体事实建立
信任。

中文核心承诺：

> **一条命令，让你的 Codex 配置在多台 Mac 间保持一致。**<br />
> 通过你掌控的私有 Git 仓库，同步 skills、agents、全局 instructions、
> 偏好设置和插件清单。

英文对应表达：

> **Keep your Codex setup in sync across Macs with one command.**<br />
> Use a private Git repository you control to synchronize skills, agents,
> global instructions, preferences, and plugin inventory.

核心承诺之后用三个简短卖点解释价值：

1. **换台 Mac，也不用重新配置**：通过同一个私有仓库恢复个人工作环境。
2. **敏感内容留在本机**：凭据、会话、缓存和机器路径不会进入仓库。
3. **每次改动都有退路**：先预检和展示计划，冲突不擅自选边，关键写入保留
   备份。

英文版表达相同事实，但使用自然英文，不逐字翻译。

## 默认语言与文件命名

GitHub 和 npm 默认展示根目录 `README.md`，因此文件职责调整为：

```text
README.md        默认简体中文
README.en.md     完整英文版
README.zh-CN.md  旧链接兼容入口
```

`README.md` 与 `README.en.md` 顶部互相链接。`README.zh-CN.md` 不再保留重复
正文，只用简短说明和链接指向 `README.md`，避免现有 GitHub、npm 历史页面或
外部链接直接失效。

用户文档也采用无后缀文件为中文、`.en.md` 为英文的规则。每一对文档顶部都
提供语言切换。

## README 阅读路径

中英文 README 使用相同章节顺序：

1. 语言切换、Banner 和核心承诺；
2. 三项产品价值；
3. 30 秒开始使用；
4. 紧凑的真实终端输出示例；
5. 第一台 Mac、另一台 Mac 与日常同步；
6. 简化的工作原理；
7. 会同步与始终留在本机的内容；
8. 常用命令速查；
9. 详细文档入口；
10. 三个常见问题；
11. 开发入口与许可证。

这条路径先回答“它能做什么”，再回答“为什么可以信任”，随后让用户完成第一
次成功操作。详细参考信息只在用户主动查找时出现。

## 快速上手与常用流程

快速上手必须明确首个版本要求 macOS、Git 和 Node.js 22 或更高版本。

第一台 Mac 的最短流程：

1. 在 Git 服务商创建一个空的私有仓库；
2. 安装 CodexKeep；
3. 运行 `codexkeep init <git-url>`。

另一台 Mac 安装后运行同一条 `init` 命令加入已有仓库。README 明确说明新设备
不使用 `link`。

日常流程只突出：

```bash
codexkeep sync
```

需要先升级第三方来源时使用 `codexkeep update`，排查问题时先运行
`codexkeep check`。直接运行 `codexkeep` 会打开当前中文交互菜单。

## 视觉资产与终端示例

首屏只保留一张真正承担品牌识别的产品横幅
`docs/assets/readme/codexkeep-banner.svg`。npm 版本、Node.js 要求和 MIT
许可证不使用 Shields.io 徽章：Node.js 22 要求在快速上手附近用正文说明，
许可证保留在 README 底部，npm 当前版本不占用首屏。

横幅采用“概念生成、矢量重绘”的混合流程：

1. 在不包含正文文字的前提下生成两至三张概念稿，只比较整体气质、构图和
   视觉重心；
2. 用户选定方向后，不直接使用生成的位图，也不自动描摹，而是在固定
   `1600 × 360` 画布中重新绘制为 SVG；
3. SVG 使用明确的安全边距、网格和固定宽高比，品牌区与同步意象在横向和
   纵向上保持平衡，不依靠浏览器压缩纠正构图；
4. 图片内只允许 `CodexKeep` 品牌名和不依赖语言的同步图形。中文与英文
   核心承诺继续由 Banner 下方的 Markdown 承担；
5. 除品牌名外不在图片中放置需要本地化的文字；品牌字形需在目标平台稳定
   渲染，必要时转为矢量路径；
6. 横幅保持轻量、无脚本，并提供准确替代文本。

生成式图片只作为设计参考，不作为最终仓库资产。这样可以利用生成工具探索
风格，同时保留 SVG 在清晰度、体积、可编辑性和多尺寸渲染上的优势。设计质量
由最终构图和验收决定，而不是由图片生成工具或 SVG 格式本身保证。

删除 `docs/assets/readme/codexkeep-demo.gif` 及两份 README 中的引用。终端演示
改为本地化代码块，只展示一个紧凑、真实且稳定的同步片段。代码块不伪造尚未
实现的输出，不包含真实用户名、远程地址、凭据或机器路径。

README 不再使用默认 Mermaid 图。同步流程通过简短正文和“会同步 / 始终留在
本机”的对照表表达，避免出现与横幅风格不一致的第二套图形语言：

```text
本机可移植配置 → 完整预检 → 用户的私有 Git 仓库 → 另一台 Mac
```

凭据、会话、缓存和机器路径从主流程分离并明确标为始终留在本机。

## README 保留的内容边界

命令速查只用一句话说明以下入口：

- `codexkeep`
- `codexkeep init [git-url]`
- `codexkeep sync`
- `codexkeep update`
- `codexkeep check`
- `codexkeep remote [git-url]`
- `codexkeep link`

README 不再为每条命令重复网络访问、文件改动、确认、冲突和恢复字段。

README 保留三项关键安全保证：

1. 文件修改前完成完整预检并展示计划；
2. 内容冲突要求用户明确选择，`--yes` 不会自动猜测；
3. 凭据、会话、缓存和机器专属路径始终留在本机。

“会同步 / 始终留在本机”使用短对照表，只列用户容易识别的内容类别。完整字段
白名单和内部路径不在主 README 展开。

FAQ 只保留：

- 为什么跨设备同步应该使用私有仓库；
- 新设备应该使用 `init` 还是 `link`；
- 同步失败或出现冲突时配置是否会丢失。

开发部分保留安装依赖和运行检查的最短命令，并链接
`docs/IMPLEMENTATION.md`。发布流程的内部细节不再占用用户 README。

## 双语详细文档

新增两组用户文档：

```text
docs/commands.md
docs/commands.en.md
docs/safety-and-recovery.md
docs/safety-and-recovery.en.md
```

### 命令手册

`commands.md` 与 `commands.en.md` 接收当前 README 的完整命令说明。每条命令
继续使用一致结构：

- 适用场景；
- 调用方式与参数；
- 网络访问；
- 可能的改动；
- 确认和 `--yes`；
- 冲突与停止条件；
- 失败后保留的状态和安全下一步。

### 安全与恢复指南

`safety-and-recovery.md` 与英文版接收：

- 完整同步与排除范围；
- `~/.codexkeep` 数据模型；
- 官方路径符号链接；
- 可移植配置白名单及本机配置合并；
- 备份位置；
- 常见失败、保留状态和恢复步骤；
- 从主 README 移出的技术型 FAQ。

现有 `docs/IMPLEMENTATION.md` 继续面向维护者，不进入新用户的主要阅读路径，也
不与用户指南重复实现细节。

## 一致性与维护规则

- 中文 README 和英文 README 的章节、命令、默认值与安全保证必须对应。
- 每一组详细文档必须覆盖相同事实，但允许自然语言结构不同。
- 公共 CLI 行为变化时，同时更新对应的中英文 README 摘要和详细说明。
- README 中的摘要不能引入详细文档没有支持的承诺。
- 事实来源优先级为当前实现、CLI 测试和帮助输出；旧 README 不是独立事实
  来源。
- 不使用需要额外 Markdown 扩展或外部脚本的布局。

## 降级与错误处理

- Banner 加载失败时，紧邻的标题、核心承诺和快速上手仍能完整表达产品用途。
- 旧中文链接通过 `README.zh-CN.md` 兼容入口到达新的默认中文 README。
- 主 README 中的语言切换和详细文档入口使用 GitHub 绝对地址，确保 GitHub 与
  npm README 页面都能正确跳转；仓库内详细文档之间的语言切换使用相对路径。
- 如果某项命令行为无法从实现或测试确认，不在 README 中猜测；保留现有准确
  描述或暂停迁移该段，直到事实得到确认。

## 测试与验收

更新 `tests/readme.test.mjs`，验证：

- `README.md` 是中文默认文档，并链接 `README.en.md`；
- `README.en.md` 链接回 `README.md`；
- `README.zh-CN.md` 明确指向默认中文文档；
- 两组详细文档存在且语言链接互通；
- 两份主 README 包含安装、首次设备、新设备、日常同步、命令速查、安全摘要、
  详细文档入口和许可证；
- 两份主 README 覆盖全部公共命令；
- 不再引用已删除的终端 GIF；
- Banner 引用有效且体积受控；
- 文档中没有真实用户主目录、凭据或私有远程地址。

实现完成后运行：

```bash
pnpm check
pnpm test
pnpm build
npm pack --dry-run
git diff --check
```

人工验收包括：

- 横幅先按完整 `1600 × 360` 画布单独评审，不使用会改变纵横比的三栏缩略图
  代替成品验收；
- 分别在 GitHub 常见内容宽度、800px 和 400px 渲染横幅，确认 SVG 保持纵横
  比且没有挤压、裁切、视觉重心偏移或失去辨识度；
- 在桌面宽度与窄屏宽度下检查标题、表格和代码块，确认没有超宽表格、异常
  字距、模糊文字或水平滚动；
- 核对中文与英文的命令、默认值、安全边界和文档链接；
- 检查 npm tarball 默认使用中文 `README.md`，其中的英文与详细文档入口能
  通过 GitHub 绝对地址访问；
- 确认没有 CLI 行为、运行时依赖或用户数据变更。

## 完成标准

满足以下条件时，本次重构完成：

- 新用户能在首屏理解 CodexKeep 的核心价值和 macOS 范围；
- README 能引导第一台和另一台 Mac 完成正确初始化；
- 关键隐私与恢复保证无需打开详细文档即可理解；
- 完整命令、安全和恢复说明仍能从双语文档入口找到；
- 默认中文、英文切换和旧中文链接兼容均有效；
- 不可读的 GIF、通用徽章和默认 Mermaid 已移除，唯一横幅在实际渲染宽度下
  清晰、平衡且可辨识；
- 自动检查和人工视觉检查全部通过。
