# 交互式状态检查 skill 整理设计

## 目标

当交互式“查看状态”发现 `~/.codex/skills` 中仍有非内置 skill 时，
CodexKeep 不再只输出一个笼统的失败计数并结束。它应先说明这些条目与
CodexKeep 仓库的实际关系，再允许用户直接回车进入现有的安全整理流程。

本次改动发布为 `v0.1.3`。

## 术语与问题分类

“位于旧目录”描述存放位置，不代表条目一定是重复副本。
`~/.codex/skills` 中除 `.system` 和 `.DS_Store` 外的每个条目，都要与
`~/.codexkeep/skills` 中的对应条目比较，并归入以下一类：

- **重复副本（duplicate）：** 两边内容相同，或者旧目录符号链接已经指向
  仓库中的普通条目。整理时备份并移除旧目录副本。
- **仅存在于旧目录（legacy-only）：** 仓库没有同名条目。整理时先备份，
  再导入仓库并移除旧目录副本。
- **内容冲突（conflict）：** 两边存在同名条目但内容不同。整理前必须由用户
  选择保留仓库版本、保留旧目录版本，或逐个选择。

状态页不得再把所有条目统称为“可能重复加载”或“旧版 skill”。

## 交互流程

`codexkeep check` 继续完成现有全部诊断，但使用现有
`inspectLegacySkills` 检查旧目录，而不是只统计文件名。发现条目时输出分类：

```text
! 旧目录 ~/.codex/skills 中发现 7 个非内置 skill
  + 4 个重复副本
  + 2 个仅存在于旧目录
  + 1 个内容冲突
```

三类计数始终全部显示，包括值为零的分类，避免用户误以为某类尚未检查。

在交互式终端中，且命令未使用 `--yes` 时，状态检查随后提供默认确认：

```text
? 现在安全整理这些 skill？ (Y/n)
```

- 回车或选择“是”后，进入与 `codexkeep link` 共用的整理流程。这个确认就是
  对分类中这些 skill 的整理授权；没有内容冲突时不再重复询问一次相同的确认。
- 有内容冲突时，继续使用现有的整批或逐项保留选择。
- 冲突选择完成后展示整理计划和备份位置，并执行完整预检；用户对冲突版本的
  选择同时构成相应替换操作的授权。
- 用户拒绝任一步骤时，不修改任何文件。
- 整理完成后，明确报告备份位置；仓库内容发生导入或替换时，继续提示运行
  `codexkeep sync`。

为了避免检查和连接命令出现两套迁移规则，冲突选择、计划生成、备份、迁移与
回滚逻辑必须由两条命令共用。`check` 只负责诊断、展示分类、取得一次整理确认
并调用共用流程；它不顺带修复其他链接或状态问题。

## 只读边界

以下调用继续保持只读：

- 标准输入或标准输出不是 TTY 的 `codexkeep check`；
- `codexkeep check --yes`；
- 用户在交互提示中选择“否”或取消。

这些场景仍输出分类结果、`codexkeep link` 修复指引和非零退出码，不创建备份，
也不修改仓库或 `~/.codex/skills`。

保留 `check --yes` 的只读语义，是为了避免现有脚本因为 `--yes` 而从诊断命令
意外升级为文件修改命令。

## 安全与错误处理

- 使用检查阶段得到的分类只做展示；真正修改前必须重新检查指纹与路径状态。
- 任何机器绝对路径、目录外符号链接或不支持的文件类型仍拒绝写入仓库。
- 修改前完成旧目录与待替换仓库条目的可验证备份。
- 后续步骤失败时继续使用现有回滚；回滚也失败时报告可手工恢复的备份目录。
- `.system`、插件 bundle 和 Codex 管理内容始终不参与分类或整理。

## 测试

新增或调整测试覆盖：

1. 状态输出分别显示重复副本、仅旧目录存在和内容冲突的数量。
2. 交互式状态检查默认确认后进入共用整理流程。
3. 内容冲突仍要求选择保留哪边，并按选择得到正确仓库内容。
4. 用户拒绝整理时两边内容不变。
5. 非交互式 `check` 保持只读，输出分类和 `codexkeep link` 指引。
6. `check --yes` 即使运行于 TTY 也保持只读。
7. 现有 `link` 的备份、回滚、符号链接安全和 `--yes` 冲突保护继续通过。

发布前运行 `pnpm check`、`pnpm test` 和 `pnpm build`。

## Shell 补全结论

用户通过 `npm install -g codexkeep` 安装后，完整命令可以正常运行；
重启终端后 `codexk<Tab>` 也已恢复。根因是 shell 在全局安装新命令后尚未刷新
PATH 命令缓存，不是 CodexKeep 缺少子命令 completion。

本次不添加命令别名、不安装 completion 脚本，也不修改用户 shell 配置。
