# 清理旧版 Codex skill 重复加载

## 目标

当个人 skill 同时存在于 CodexKeep 管理的 `~/.agents/skills` 和旧版
`~/.codex/skills` 时，`codexkeep link` 应提供可以直接回车接受的安全修复，
最终只从标准位置加载一份个人 skill。

`~/.codex/skills/.system` 属于 Codex 内置内容，始终不读取、不移动、不纳入
同步。

## 现状

`codexkeep check` 会报告 `~/.codex/skills` 下的非内置条目，但只输出“可能
重复加载”，没有修复入口。`codexkeep link` 只检查五个受管理链接；当这些链接
已经正常时会提前退出，因此无法处理旧版 skill。

个人 skill 的标准来源是 CodexKeep 仓库中的 `skills/`，通过
`~/.agents/skills` 链接供 Codex 加载。`~/.codex/skills` 只应保留 `.system`。

## 修复模型

新增一个独立的旧版 skill 迁移服务。服务扫描 `~/.codex/skills` 的顶层条目，
忽略 `.system` 和 `.DS_Store`，并与 CodexKeep 仓库 `skills/` 中的同名条目按
完整内容指纹分类：

1. **相同副本：** 两边同名且指纹相同。保留仓库版本，归档旧目录副本。
2. **仅旧目录存在：** 将旧 skill 导入仓库，再归档旧目录副本。
3. **内容冲突：** 两边同名但指纹不同。必须先决定保留仓库版本还是旧目录版本。

迁移完成后，所有非内置个人 skill 都只存在于仓库的 `skills/` 中；旧目录仅
保留 `.system` 以及被明确忽略的 `.DS_Store`。

## 交互

`codexkeep link` 在验证仓库和链接状态后、任何修改前完成旧版 skill 预检。
即使五个链接已经正常，只要发现旧版 skill，也继续进入修复流程。

没有内容冲突时，命令展示完整计划：

- 清理多少个完全相同的旧副本；
- 导入哪些仅存在于旧目录的 skill；
- 备份将保存到哪里。

确认项默认选中“修复”，用户可直接回车执行。非交互环境未传 `--yes` 时仍不做
修改；传入 `--yes` 时可以自动执行无冲突迁移。

存在内容冲突时，交互模式先提供以下选择：

1. 保留 CodexKeep 仓库版本（推荐用于新机器）；
2. 保留 `~/.codex/skills` 旧版本；
3. 逐个冲突选择；
4. 取消。

全局选择只作用于内容冲突；完全相同和仅旧目录存在的条目仍按上述固定规则
处理。`--yes` 不替用户解决内容冲突，而是列出冲突名称、保持两边不变，并提示
不带 `--yes` 重新运行 `codexkeep link`。

如果没有待建链接也没有旧版 skill，保留现有“当前设备已经连接，无需修改”
结果。若链接和 skill 都需处理，则合并成一次计划和一次最终确认。

`codexkeep check` 保持只读。发现旧版 skill 时，除现有警告外明确输出
“运行 codexkeep link 可安全合并并清理旧副本”。

## 写入与恢复

所有选择和文件指纹都在写入前完成，保证完整预检。迁移使用
`~/.local/state/codexkeep/backups/legacy-skills-<timestamp>/`，其中分别保存：

- 从 `~/.codex/skills` 移出的全部旧条目；
- 用户选择旧版本时被替换的仓库条目。

执行顺序为：

1. 创建唯一备份目录；
2. 将需要替换的仓库条目移入备份；
3. 将所有旧目录条目移入备份；
4. 从备份复制仅旧目录存在或被选择的旧版本到仓库；
5. 创建计划中的缺失链接。

迁移服务记录每一步。如果任一步失败，删除本次新导入的仓库条目、恢复被替换的
仓库条目，并把旧目录条目移回原位。链接仍使用现有的创建回滚；命令只有在 skill
迁移和链接创建都成功时才报告完成。备份目录成功后保留，并在输出中显示路径。

为了避免两个独立事务互相成功一半，命令先执行 skill 迁移，再创建链接；如果
后续链接创建失败，迁移服务也执行回滚。实现应通过一个命令级事务协调这两项
操作，而不是让服务自行提前提交。

## 边界

- 不修改或链接 `~/.codex/skills` 根目录。
- 不处理 `.system` 内的任何内容。
- 不自动提交或同步迁移产生的仓库变更；完成后提示运行 `codexkeep sync`。
- 不新增依赖。
- 不把 `check` 改成写命令。
- 不把无关的 plugin、agent 或配置迁移纳入本次修改。

## 测试

新增服务级和命令级测试，至少覆盖：

- 完全相同的副本默认保留仓库版本并归档旧副本；
- 仅旧目录存在的 skill 被导入仓库；
- 内容冲突可全局选择任一边；
- 内容冲突可逐个选择；
- 取消和 `--yes` 遇到冲突时不修改任何文件；
- `.system` 和 `.DS_Store` 不受影响；
- 五个链接已正常时仍可执行迁移；
- 链接和迁移合并为一次确认；
- 迁移中途失败以及后续链接失败时恢复两边原内容；
- `check` 输出明确的 `codexkeep link` 修复指引；
- 无旧版 skill 时保持现有幂等行为。

实现完成后运行 `pnpm check`、`pnpm test` 和 `pnpm build`。
